# План реализации: задачи по ТЗ «Сбор социальной активности и геймификация сообществ»

Источник: `SPEC.md` v1.0 от 15.10.2026. Ссылки вида **§8.1** ведут на разделы ТЗ.

## Как пользоваться

- Задачи идут в порядке выполнения. Каждая задача — один законченный шаг: после неё сервис запускается, миграции применяются, тесты проходят (§20).
- Формат задачи: **Цель → Что сделать → Готово, когда (DoD)**. В «Зависит от» указаны задачи, которые нужно закрыть раньше.
- 🧑 — задача требует действий человека: реальный ключ сообщества ВК, тестовое сообщество, VDS, внешнее хранилище для бэкапов.
- 🔬 — исследовательская задача. Её результат — документ или решение, а не только код.
- Сквозные правила для всех задач (не повторяются в каждой):
  - всё tenant-scoped: запросы и задания выполняются в контексте `organization_id`, доступ проверяется на сервере (§5);
  - секреты, токены, коды подтверждения и тела личных сообщений не попадают в логи, inbox, error tracker и аналитические представления (§8.1, §16);
  - время хранится в UTC (`timestamptz`), баллы — integer или `numeric`, не float (§10);
  - внутренние PK — UUID, внешние ID — строки (§10);
  - неизвестное и пробелы не показываются как ноль (§9, §12);
  - заглушки допустимы только для явно будущих интеграций (Instagram, Facebook, TikTok, Apify), и в интерфейсе они помечены как недоступные (§1, §2).

> Текущий репозиторий содержит Python-скрипт `vkcover.py`. Новый сервис — отдельное Rails-приложение. Рекомендуется вести его в отдельном репозитории или в каталоге `app/` верхнего уровня; решение принимается в задаче T0.1.

### T1.2 Docker Compose для разработки и production
- **Зависит от:** T1.1
- **Что сделать:**
